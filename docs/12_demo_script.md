# Stakeholder Demo Script

**Author (persona):** Technical Writer / GenAI Developer
**Audience:** Product Owner, hiring panel / engagement stakeholders

## 1. Setup (before the room)

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python scripts/run_pipeline_demo.py     # runs ETL -> chunk -> embed -> index on sample_docs, prints a report
uvicorn src.api.main:app --reload       # start API on :8000
```

## 2. Narrative

1. **"Here's the raw problem."** Show `data/sample_docs/` — a handful of heterogeneous docs (txt/html/json) standing in for scattered internal knowledge.
2. **ETL in action.** Run `POST /ingest`. Show the manifest response — documents processed, chunk counts, checksums. Point at `src/etl/pipeline.py` to show the extract→transform→load stages and their logging.
3. **Ask a grounded question.** `POST /query` with a question answerable from the corpus. Show the answer *and* the citation chunk ids — "every claim traces back to a source, that's the RAG grounding contract."
4. **Show the hybrid advantage.** Re-run the same query with `alpha=1.0` (pure dense) and `alpha=0.0` (pure lexical) vs. the default hybrid weight; reference `docs/11_rag_evaluation_report.md` for the measured hit-rate/MRR delta.
5. **Ask a multi-step question.** `POST /agent/run` with a goal requiring two lookups + a synthesis step. Walk through the `steps[]` trace — "this is the planner deciding what to retrieve, not a hard-coded pipeline."
6. **Show the fine-tuning spike.** Open `docs/10_finetuning_experiment_report.md` — before/after metrics from the LoRA domain-adaptation experiment.
7. **Show it's production-shaped, not a notebook.** `docker build`, then `kubectl apply -f infra/k8s/` (or explain why not applied live), then the GitHub Actions run (`infra/ci-cd/.github/workflows/ci-cd.yaml`) — lint, test, build, all green.
8. **Show observability.** Hit `/metrics`, point out latency histogram and `retrieval_hit_rate` gauge; reference the Grafana dashboard stub and alert rules.
9. **Close on traceability.** Open `docs/13_jd_traceability_matrix.md` — "every requirement in the job description maps to a file you just saw run."

## 3. Fallback if live demo isn't possible

`EVIDENCE.md` (generated by `scripts/run_pipeline_demo.py` and the test suite) contains captured console output from an actual end-to-end run in the reference environment, plus the pytest summary, as a static artifact.
