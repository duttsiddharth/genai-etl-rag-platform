DocuMind AI Platform Overview

DocuMind AI is an internal Generative AI platform that turns scattered company documents into a governed, queryable knowledge base. The platform ingests PDFs, HTML pages, plain text files, and exported support tickets, then makes their content available through a hybrid retrieval-augmented generation (RAG) API and an agentic research assistant.

The ingestion pipeline follows a classic ETL pattern. The extract stage reads raw files and pulls out text and metadata regardless of source format. The transform stage cleans the text, collapses whitespace, strips control characters, and applies a PII-scrubbing hook that redacts emails and phone numbers before anything is stored. The load stage writes the normalized document to a processed store and appends an entry to an audit manifest that records the document id, a content checksum, and the number of chunks produced. Because the manifest is keyed on checksum, re-ingesting an unchanged document is skipped automatically, which keeps the pipeline idempotent.

After loading, each document is split into retrieval-sized chunks. Three chunking strategies are supported: fixed-size windows with overlap, a recursive splitter that respects paragraph and sentence boundaries, and a semantic splitter that groups sentences until an embedding-similarity breakpoint is crossed. The recursive strategy is the default because it balances chunk coherence with predictable size.

Each chunk is embedded into a vector and stored in a vector database alongside its source metadata. The platform also builds a lexical BM25 index over the same chunks. When a user asks a question, the hybrid retriever queries both indexes and fuses the two score lists using a weighted formula: fused_score equals alpha times the dense similarity score plus one minus alpha times the normalized BM25 score. The default alpha is 0.6, meaning retrieval leans semantic but still benefits from exact keyword matches, which matters a lot for questions that mention specific error codes, product names, or ticket numbers that a purely semantic model might blur together.

The retrieved chunks are assembled into a grounded prompt and passed to a language model, which is expected to answer only from the provided context and to avoid asserting anything the context does not support. Every answer returned by the API includes the chunk ids it was grounded in, so any claim can be traced back to its source document.

For more complex questions that require multiple lookups, the platform exposes an agent orchestrator. The agent plans a sequence of steps, calls tools such as the retrieval tool or a calculator tool, observes the results, and only produces a final answer once it has gathered enough evidence or hit its step budget. The step budget exists specifically to bound cost and latency, since an ungoverned agent loop can otherwise make an unbounded number of expensive model calls.

The platform is designed to run on any of the three major cloud providers. Object storage and managed model access are both hidden behind a provider-agnostic interface, so swapping from AWS S3 and Bedrock to Azure Blob Storage and Azure OpenAI, or to Google Cloud Storage and Vertex AI, is a configuration change rather than a code change.
